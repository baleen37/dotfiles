# `bgc` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a macOS-only `bgc` zsh command that reports cache sizes and performs confirmed, safe cache cleanup without changing the existing `gc` git alias.

**Architecture:** Define `bgc` in the existing zsh function module, guarded by `isDarwin`. The command has `stats`, `--dry-run`, `help`, and default cleanup modes; cache measurement uses `du`, cleanup commands are best-effort, and Docker is a separately confirmed stage.

**Tech Stack:** Nix, Home Manager, zsh, Nix derivation assertions.

## Global Constraints

- `gc = "git commit"` remains unchanged.
- The command is defined only for macOS.
- Default cleanup never deletes project files, app settings, Nix profiles/generations, Docker named volumes, or running Docker containers.
- `bgc` asks for confirmation before normal cleanup and asks separately before Docker cleanup.
- Missing paths or missing optional CLIs do not abort the remaining cleanup.

### Task 2: Implement the minimal macOS `bgc` command

**Files:**

**Interfaces:**

- Produces: the interactive `bgc` zsh function with `stats`, `--dry-run`, `help`, and cleanup modes.

- [ ] **Step 1: Add the Darwin guard to the import**

Change the utility-function import to pass `isDarwin`:

```nix
${import ./functions.nix { inherit isDarwin; }}
```

- [ ] **Step 2: Add cache measurement helpers and command parsing**

In `functions.nix`, use `lib.optionalString isDarwin` around a single-quoted zsh body. Define a local `bgc_size` helper that prints `0B` for missing paths and otherwise uses `du -sh`. Define `bgc_stats` with explicit labels for Homebrew, Nix, Node, Python, Gradle, Xcode, and `~/Library/Caches`.

Handle only these arguments:

```zsh
bgc stats
bgc --dry-run
bgc help
bgc
```

Unknown arguments print usage and return status 2.

- [ ] **Step 3: Add confirmed cleanup stages**

The default mode calls `bgc_stats`, asks one `read -q` confirmation for normal caches, and runs best-effort cleanup commands only when their executable/path exists. It then asks a separate confirmation with the exact text `Docker cleanup` before running:

```zsh
docker container prune
docker image prune
docker builder prune
```

Do not call `docker volume prune`, and do not use `nix-collect-garbage -d`.

`--dry-run` prints the same stats and the commands that would be considered without executing cleanup. `stats` does not prompt.
