# ADR 0002: 도구·시크릿 준비와 호스트 적용을 분리한다

- 상태: 채택 — CLI 옵션과 키 필수 정책은 [ADR 0004](0004-local-bootstrap-switch-contract.md)로 대체
- 날짜: 2026-11-08
- 결정·운영 책임자: dotfiles 관리자

## 배경과 결정

새 머신의 도구 설치·인증·키 복원과 기존 머신의 구성 적용은 필요한 권한과
실패 원인이 다르다. 하나의 명령에서 모두 수행하면 구성 적용 중에 설치나
금고 인증이 시작되고, 어느 준비 단계까지 끝났는지 판단하기 어렵다.

`bootstrap.sh`는 필요한 도구와 기존 age identity를 준비하며 전체 호스트를
활성화하지 않는다. 기존 유효한 키는 보존하고, `--skip-secrets`는 키 복원만
생략한다. 준비가 끝나면 사용자가 별도로 `switch.sh`를 실행한다.

`switch.sh`는 도구와 선택한 구성의 준비 상태를 검사하고, 실제 적용 전에는
시크릿 검사를 수행한다. 도구 설치나 1Password 인증·키 복원은 시작하지 않는다.
준비가 부족하면 bootstrap 실행을 안내하고 중단한다.

## 검토한 대안과 결과

설치·인증·적용을 한 명령으로 묶으면 최초 실행은 짧아지지만, 반복 적용에도
초기 설치 책임이 섞인다. 두 명령을 유지해 초기 준비 후에는 switch만 반복한다.
bootstrap 성공은 실제 호스트 활성화 성공을 뜻하지 않는다.

`switch.sh --build`는 활성화 없는 별도 검증 경로이며 시크릿 검사를 생략한다.
따라서 빌드 성공만으로 금고 인증·복호화·시스템 적용이 검증됐다고 보고하지 않는다.
macOS 앱 관리 권한은 [ADR 0001](0001-macos-permission-preflight.md)을 따른다.

## 후속 작업과 검증

두 공개 CLI를 각각 실행하고 bootstrap의 비활성화, 준비가 부족한 switch의
거부, build-only의 비활성화를 확인한다. 정상 적용은 별도로 실행해 검증한다.
sudo 인증 정책의 변경은 이 역할 분리와 별개의 결정으로 기록한다.
