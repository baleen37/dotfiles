# Domain docs

단일 컨텍스트 구성이다.

코드 탐색 전에 루트 GLOSSARY.md와 작업 영역에 관련된
docs/adr/ 문서를 읽는다. 없는 문서는 건너뛴다.

용어는 GLOSSARY.md의 정의를 따른다.
기존 ADR과 충돌하는 제안은 해당 ADR과 변경 이유를 명시한다.

용어와 결정이 확정될 때 core:domain-modeling으로 문서를 갱신한다.

## ADR

ADR은 되돌리기 어려운 결정과 그 이유를 짧게 남기는 문서다.
`docs/adr/NNNN-slug.md`로 번호를 하나씩 올려 만든다.

쓰는 때: 아래 세 가지가 모두 맞을 때만.

1. 되돌리기 어렵다.
2. 맥락 없이 보면 "왜 이렇게 했지?" 싶다.
3. 실제로 다른 선택지가 있었고, 이유가 있어 하나를 골랐다.

형식: 제목과 1~3문장이면 충분하다. 상태(제안·채택·대체됨)와 날짜를 적는다.
검토한 대안이나 결과는 나중에 읽는 사람에게 꼭 필요할 때만 쓴다.

결정을 바꿀 때는 기존 ADR을 고치지 않는다. 새 ADR을 쓰고,
기존 ADR의 상태를 "대체됨: ADR NNNN"으로 바꾼다.
